# Retail sales, tax and private owner commission

## Where to find it

Showroom Admin has a Retail Sales & Tax Report link, available to staff with Reports read permission. The existing invoice reports page also links to it. The separate Private owner commission link is rendered only for the primary owner's exact Firebase UID and email. Its server endpoint independently verifies that identity, verified email, active owner role, recent password authentication and a TOTP second factor. General managers and other staff are rejected regardless of permissions.

## One-time owner authenticator setup

Firebase Authentication must already use Identity Platform. The owner Connect authenticator app action now enables TOTP through the Admin SDK after verifying the exact primary owner, active owner role and password reauthentication within two minutes. Firebase's Sign-in method console screen can show only SMS MFA; do not direct the owner to an absent TOTP toggle. This narrow setup endpoint can only enable TOTP support and cannot read commission data, enroll/un-enroll accounts, disable SMS, or remove an existing authenticator. Private ledger APIs still require a fresh password plus a verified TOTP second factor. Do not report enrollment as complete until the owner scans and verifies the authenticator. Enabling Identity Platform can change Firebase billing limits; review its console terms before enabling. No upgrade or new paid service is activated by this code.

Sign in as the primary owner, visit /owner/retail-commission, enter the existing website password, and click Connect authenticator app. The website service account must have Authentication configuration read/update permission; otherwise setup returns an actionable error and remains locked. Scan the QR code and confirm its six-digit code. Re-enter the password and a current code to unlock. Owner sign-ins then require MFA; both email/password and Google sign-in handle TOTP challenges. The private area requires password-based step-up even if the main account used Google sign-in. The owner must have a password provider linked to the same Firebase account. An enrollment factor alone is insufficient: the server checks the verified token's sign_in_provider=password, sign_in_second_factor=totp and auth_time within five minutes. Refreshing an ID token cannot extend this window. Unlocking a locked rate requires authentication within one minute.

Secrets and OTP verification are managed by Firebase. The app does not implement a separate OTP protocol, collect the password in its server APIs, or store MFA secrets in Firestore/local storage. Keep a secure backup of the authenticator using its supported backup tools. Lost-factor recovery uses the Firebase project's authorized account-recovery process; there is no staff-accessible bypass in this app.

## Report basis

Reports use the current main invoices collection, the latest archived copy of each deleted invoice, and confirmed paid showroom_live_orders. Canonical online payments replace showroom_orders display mirrors and explicitly linked invoice copies. Ambiguous older storefront orders and duplicate invoice numbers are flagged for review. Drafts, consignment, wholesale, cleaning, repair and mixed service invoices are excluded or flagged.

A completed sale means fully paid (explicit Paid terms with no payment ledger is accepted for legacy cash invoices; otherwise the payment amounts must settle the net invoice). Unpaid and part-paid invoices are listed but excluded from totals. Reports are management summaries on this fully paid basis, not a new tax calculation or filing. They use the invoice engine's recorded-calculation tax outputs; its newly exposed netSalesTax is the existing net tax result, with no calculation formula changed.

Gross sales less discounts and merchandise refunds equals net sales. Tax is net of refunded tax. Grand total reconciles with net sales, tax and other invoice charges / cent rounding. Refunds restate the original sale month; the older data has no separate dated refund journal. Full online refunds are automatic. A partial online refund lacking item/tax components is excluded until Reports-write staff confirms a split matching the verified refund total. The split is audited and invalidated if the refund changes. Unresolved records mark exports Draft. PDF/Excel include invoice rows, totals, status and warnings. The source loader rejects more than 20,000 records per source rather than silently truncating totals.

## Commission accounting

Default rate is 10%. Eligible basis is completed retail merchandise after discounts and refunds, excluding tax, shipping and other charges. A saved rate is retained per sale. New fully paid retail invoices capture a completion timestamp when saved or settled; generic address edits do not reset it. Legacy records use payment dates or invoice creation dates until first reconciliation. New rates have an immutable server timestamp and apply to later completions. Reconciliation adjusts commissions for refunds/discount changes using that sale's saved rate. Rate lock is enforced server-side, and changes use version checks and an audit trail. Missing sales sources remain flagged for owner review rather than silently deleting accrued commission. There are no transfers or processor charges.

Record any positive amount received, its actual date, method and optional reference. Apply it to a commission month or keep it unallocated. Unallocated receipts can be split across months later, including partial amounts. Overpayments are shown as credit; monthly and yearly balances are earned less allocated receipts, while the overall balance uses all received payments. Mistakes can be voided with a reason; the original receipt and audit history stay saved. UUID operation receipts and transactions prevent duplicate submissions and over-allocation from competing browser tabs.

Private collections owner_commission_private, owner_commission_accruals, owner_commission_payments and owner_commission_actions are accessed only with Admin SDK after owner verification. Existing Firestore rules do not grant client access to these unknown collections. Private data is not placed in general reports, customer documents, invoice payloads or browser persistence. APIs use no-store responses and the UI clears its loaded data when the private session expires or sign-in changes.
