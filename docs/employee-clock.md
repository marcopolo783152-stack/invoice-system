# Employee QR clock-in upgrade

Deploy this change, then open **Employees → Print Shop QR** and reprint employee **QR Badge** cards. Older QR codes did not authorize kiosk access and must be replaced. **Copy clock-in link** provides the same permanent authorized link. Employees do not need a Firebase account login. Browser camera and precise location permissions are still required. The exact `/admin/invoices/clock` route bypasses the staff login gate; all other admin routes retain it.

The manager may **Replace / revoke old QR** to invalidate all earlier links for the store and print replacements. QR images are generated locally without sending the capability link to a third-party QR service. Links place the random 256-bit kiosk key in the URL fragment, remove it from the address after opening, and send it only as a header to the clock APIs. The private key documents remain unavailable to browser Firestore clients under existing default-deny rules. Do not share kiosk links outside staff.

A valid kiosk key exposes only employee names, employee IDs, current IN/OUT status and existing face descriptors required for local matching. It does not expose payroll, PINs, phones, emails or dashboards. The key is scoped to one store collection; no cross-store or fuzzy name/phone matching is performed. ID/PIN lookup must match exactly and uniquely. Old badges with only an employee ID require reprinting.

Face clock-in now requires exactly one clearly detected face, a distance at most 0.43, at least a 0.10 margin over the second candidate, and four consistent frames. The employee confirms their displayed name and explicitly chooses IN or OUT. The server rechecks the descriptor, confirmed employee and badge identity. Uncertain matches never auto-clock someone else. Face recognition is not liveness verification or a guarantee of identity; an exact ID/PIN fallback remains available. Bad or duplicated existing face registrations should be replaced by the manager using separate employees in good light. Registration rejects multiple faces and blocks a descriptor too similar to a different existing employee.

Clock records use Firebase Admin server transactions, server timestamps and deterministic operation IDs. Employee status and time log are saved together. Retrying the same operation does not create duplicates. Concurrent IN attempts cannot toggle attendance back OUT. Opposite actions within 30 seconds are blocked. Failures never show a saved result. The existing shop location and 200-foot radius remain, with finite coordinates and location accuracy checks. Location supplied by a browser is not tamper-proof.

Existing attendance history and payroll remain intact. The public kiosk no longer runs broad auto-clock-out, store searches, payroll dashboards or browser writes. The existing staff attendance tools keep their existing auto-close workflow.

Verified by `tests/access/employee-clock.test.mjs`, TypeScript and a production build. Actual staff face similarity, mobile camera permissions, precise GPS and production Firebase records still need a real device check after deployment. If stricter matching rejects an employee, use ID/PIN and re-register their face; do not loosen thresholds blindly.
