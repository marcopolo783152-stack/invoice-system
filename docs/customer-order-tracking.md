# Customer order tracking

Deploy the latest branch to Vercel Production. Open `/?view=track` or the Track your order link in a new payment receipt. A guest enters the order number plus the exact email used at checkout; no account is required. Existing references such as MP-000015 and original MPR-LIVE receipt IDs remain usable. Invalid email/reference pairs receive the same not-found response. There is no public email-only or phone-only order search.

New online orders receive a cryptographically random reference with mixed letters and numbers, for example MP-K7A209FCE314. A Firestore transaction reserves each reference, writes it to both order records, and keeps it stable across concurrent requests and retries. Existing references are not changed, so old receipts continue to work.

Verified customer accounts can see guest purchases with the same checkout email, without rewriting the original order owner. This does not grant staff permissions. Existing account order refreshes continue to run.

The tracking page and customer account show the carrier actually saved on the shipment: carrier name, tracking number, latest carrier scan location/status, history, and ETA when the carrier supplies one. Shipment details and order status refresh every minute while tracking is open. These are carrier scan events, not a GPS position. UPS shipments link to UPS, FedEx to FedEx, and USPS to USPS. The shared helper also supports DHL Express/eCommerce, OnTrac/LaserShip and Canada Post. Unknown carriers do not silently use USPS; live integration depends on Shippo's carrier support and permissions.

Live updates use the existing SHIPPO_API_KEY on the server. It must be a live key. Labels bought through Shippo provide tracking; carrier account restrictions still apply, especially for labels purchased elsewhere. No new external tracking subscriptions or webhooks are registered by this change. Carrier provider outages show a useful message and the official carrier link. Test data is not displayed as live. Order statuses are not changed by customer browser code; existing verified server webhook handling remains responsible for fulfillment transitions.

Public tracking APIs validate the number/carrier, enforce shared Firestore request limits and return no payment secrets, shipping labels, transaction metadata, customer street addresses or phone numbers. Carrier responses expose only scan details and estimates. Lookup bodies use POST and responses are private/no-store. Only shipments saved against an order can call the carrier API; raw provider error details are not returned. Private Firebase client rules are unchanged.

Checks cover guest lookup using old receipt references, exact email/verified ownership, denial of wrong or partial credentials, concurrent request limits, private response fields, correct carrier links, provider caching, carrier/number mismatches, test key/data rejection, stable reference allocation and existing payment/label safeguards. After deployment, confirm MP-000015 with the customer's actual checkout email and its saved UPS tracking number. Production carrier responses were not exercised during local verification.
