# Customer pickup scheduling

After deployment, open **Showroom admin → Customer Pickups**. The showroom dashboard, invoice dashboard, and existing Appointments tab also show Pickup reminders with a link to schedule/manage collections. Showroom reminders open the Customer Pickups section inside showroom admin. The existing Invoice System pickup route is also retained.

1. Click Schedule pickup. Record customer name, phone, optional email, full pickup address, date/time, requested service (cleaning, repair, both, or other), estimated rug count, assigned driver and access/service notes. Times are Alexandria / America/New_York wall time. Save.
2. The booking is persisted in Firebase `service_pickup_bookings`; it is not an invoice and does not change rug stock. Active is the default list. Search by name, phone, address or driver. Edit/reschedule as needed. Cancellation requires a reason and keeps history.
3. Dashboard reminders show overdue/today pickups, the next seven days, and collected bookings still awaiting an invoice. They refresh once a minute and when a booking changes in the same page. These are in-dashboard reminders; no SMS, email, browser push or background automation is claimed.
4. After physically collecting the rugs, click Mark picked up. Then Create invoice opens the existing invoice form with service mode, customer contact/address and collection notes. The notes retain both the scheduled collection and actual pickup time. Enter actual rugs, measurements, prices and the customer return/ready pickup date. The scheduled collection date deliberately does not become the customer's ready-for-pickup date. Other service bookings can use the existing form's document/mode selector as appropriate.
5. Save normally. The server validates the invoice and calculates its amount using the existing calculation engine. The invoice, invoice-number reservation and booking's invoice link are committed in one transaction. The booking moves out of Active to Invoice created, with an Open invoice button. Repeated/concurrent saves cannot create two invoices for one pickup. If another employee changes the booking details while its invoice form is open, reload from the pickup before saving so stale information is not silently used. Invoice edits and customer email/share/payment functions continue through the existing invoice workflow.

Only staff with appointments permissions can read/manage pickups. Creating a linked invoice also requires invoices.write. Private booking information is served by authenticated server APIs; no new client Firebase permission grants are added. Linked invoices use the existing main showroom `invoices` collection. Existing invoices, prices, taxes, washing-company handoffs, auction code and stock/cart rules remain in their existing workflows.

The list loads active bookings separately from the latest 100 recent bookings, so old uncompleted collections are not hidden by new completed records. Above 500 active bookings the interface warns about the bounded view; this is not an unlimited historical export. History records are retained in Firebase.

Automated checks cover booking validation, retries, concurrent status changes, rescheduling/cancellation history, accurate prefill, number collisions, atomic invoice linkage, duplicate prevention and unauthorized/cross-origin access. Production Firebase login and real pickup/invoice entry require a staff walkthrough after deployment.
